## 2. 用户和管理员入口

- `/services`：按服务类型筛选商品；使用各插件专用表单，先读取可选计划，再预览服务器报价。
- `/service-orders`：所属用户的进度、执行记录、操作历史和可用售后动作。结果不确定时只检查状态，不自动重提。
- `/admin/service-products`：搜索、分页选择已验证接口，读取目录、设置零售价并上架；实习服务改为选择平台、填写有效期内的合同成本及核对依据，不请求不存在的目录/价格接口。商品与供应商的绑定不可更换；下架无需供应商在线。
- `/admin/service-orders`：核对不确定操作、查看上游单号和审计记录、为已核实的上游主动退款入账。
- `/admin/orders`：订单详情内的“恢复执行编号”；输入可信回执，先核对完整身份，再单独确认关联；已实现，默认关闭。
- `/admin/plugin-integrations`：保留为**管理员接口接入检查**，不是用户购买入口。此页查询目录本身不创建订单或扣款。

界面沿用现有主题变量和 Element Plus，支持移动端与深色模式。编辑无心计划回填当前配置，不用新订单的默认时间/星期覆盖旧计划。原始账号密码和授权码不存入浏览器持久化存储。

## 3. 后端架构

下图为付费服务下单流程；执行编号恢复等本地维护不进入扣款或派发链路。

```text
Vue 专用表单 → 服务端报价（READY，5 分钟有效）
                 ↓ 用户显式确认
本地事务：锁定操作 / 商品 / 订单，校验版本，记录订单与余额扣款
                 ↓ 事务提交后，仅一次上游请求
NativeServiceGatewayRouter → PhpNativeServiceGateway / WuxinNativeServiceGateway
                            / InternshipNativeServiceGateway / SsbenzDistanceGateway
                 ↓ ApiHttpClient → SafeHttpClient
本地事务：处理明确回执、更新订单、必要时记入退款账本
```

- `service_product`、`service_order`、`service_order_operation` 与既有 `account_ledger` 协作，不运行旧 PHP、SQL 或 cron。
- `PlatformDockingStrategyFactory` 仍只收录课程策略。服务提供商不能绑定课程平台，亦不能通过修改类型把既有课程配置原地转成服务配置。
- 保存配置 → 只读验证 → 显式启用；敏感配置变化使旧验证失效。订单保留供应商身份指纹，不能因换地址/账号而被重定向；既有五类服务的独立账号身份未变时可轮换密钥；P05令牌本身即账户身份，更换后旧订单不可自动迁移。
- 出站目标只来自已保存配置，保留 DNS/SSRF、TLS、重定向、超时和响应大小限制。关闭传输自动重试，不接受用户传入任意 `act` 或 URL。
- 实习使用已保存的完整直连 API 地址；GET 使用 `act/uid/key` 查询，POST 使用表单凭据，不追加清卡包装路径。习迅云学校路由只接受上游学校目录的 HTTPS 元数据，不接受客户端 URL，也不向用户返回该地址。
- 无心按原协议使用保存的 `u_uid/key` 查询凭据；学生授权码只在 POST 业务字段中发送。请求 URL 查询串、请求体和原始响应不写日志。
- DTO 只返回白名单字段、掩码账号与十进制金额字符串。敏感订单参数加密保存；已完成/过期参数清除，不确定操作的参数最长保留七天。报价与计划使用北京时间，不依赖宿主机时区。

## 4. 资金与售后约束

1. **预览不扣款**。Flash 报价最迟在最早任务时间失效；过期预览不当成已创建订单。确认时再次检查商品、供应商和订单版本；订单保留原零售单价与计费因子。报价过期或版本变化必须重新预览。
2. **不能重放写操作**。确认编号派发至多一次；HTTP 不自动重试。上游负码也可能包装超时，不能推断“肯定未受理”。
3. **结果不确定**：保存为 `UNKNOWN`，保留原扣款与待核对操作；进程中断的 `DISPATCHING` 超过五分钟也进入核对，不自动再次下单或退款。
4. **用户请求退款**：按明确回执的剩余次数、订单冻结单价结算，并以预览上限和已付净额封顶；余额、账本和订单状态同一事务更新。
5. **上游主动退款**：同步只标记 `REFUND_REVIEW`，不会凭状态字符串自动加余额。管理员查验上游单号/资金流水，填写实际次数及依据，先预览再确认本地入账；此流程没有上游写请求。Flash 未提供完成次数时不默认填入全额退款次数，须人工核实。
6. 人工核对和审计资料要求同时具备 `api-provider:update`、`payment:reconcile`。核对记录保存操作者与依据；订单所属用户看不到管理员证据和供应商凭据。
7. 单任务延期同样先预览再确认，仅使用当前订单已核实的任务 ID；不接受外来聚合订单号，不改变订单的暂停状态；结果不确定仍不自动重复提交。
8. 两个并发退款预览不能重复入账；账本写失败会回滚整个本地结算。结果响应丢失时只查询已保存编号，不补发写请求。

## 实习服务的计费与 UI

- 平台分别为职校家园、黔职通、工学云、校友帮、习迅云/宁夏、学习通、慧职教、广西职业、江西智慧教育；项目和商品 ID 必须一致。
- 不复制原插件硬编码价格。管理员核对合同服务日成本、倍率、取消条款并留下依据（最长 90 天）；售价不得低于成本，供应商身份变化或合同过期阻止新扣款，不阻断已付订单取消。
- 按北京时间今天至截止日（含首尾）和所选星期生成已购日期，一次最多 365 个日历日。节假日开关不减少已购天数；校友帮运行方式 3 的日价倍率为 5，创建后不能通过编辑换价。
- 续期/改星期只为**从未买过的日期**扣款；缩短不自动退款，恢复已经买过的日期不重复收费。立即执行单独按一次计费，不增加已购天数。新增费用四舍五入后不足一分时拒绝，而非免费追加。
- 取消采用公开的本平台未用服务日退款规则，须上游明确确认取消；按当前计划内尚未到期的已购日期、冻结日价计算，并以报价和净付款额封顶。这不代表上游返回了退款天数或承诺同额退款。
- 补交范围必须全部属于已购服务日且不晚于今天，不得跨过未购日期。界面禁选无效日期，服务端再次校验；黔职通无日报，工学云额外支持上班/下班/上下班打卡类型。
- 编辑回填当前计划，账号不可修改，空密码保留远端现有凭据。上游订单号、平台、日期/星期和运行方式必须与本地快照一致；跨零点报价重新预览。
- 订单展示已购天数与截止日，不伪造完成百分比；日志只展示最近十条的时间与安全类别，不返回可能含凭据的原文，也不把类别当作执行成功。
- 账号预检可返回独立 `advice`：上下班时间、截止日、星期与报告开关。用户点击“采用这些建议”才更改表单；未知字段不补默认值，不改变运行方式或已购日期，更换账号/学校/项目后丢弃旧建议。
- 本平台增加 ShowDoc 通知：保存本人密钥不会发送，显式验证通知、输入收到的六位验证码后才启用订单变化通知；非上游微信授权，不收取原包所谓“绑定费”。
- 通知凭据和待发送内容服务端加密；固定官方 HTTPS 目标，不接收 URL。验证码十分钟有效、最多五次尝试，重新配置后旧证明失效；订单转属后不能继承原渠道。
- 后台有界观察本地已同步状态，不额外查上游；通知只含平台订单编号、状态与计划日，不含账号密码、位置或报告。离线变化可能合并；周期结束不代表考勤成功，ShowDoc 受理不代表阅读。
- 验证与更新均有持久化发送记录；UNKNOWN 不自动重发，已收到的原验证码仍可验证。限流故障时拒绝发送；停止清除密钥并取消未派发消息，已派发内容不可撤回。通知不触发资金操作。
- 未开放：真正的校友帮微信授权及令牌采集、无可靠实现的评价/异步任务/地址搜索。原包“绑定”只有状态修改和收费，不复制为假绑定成功。

## Benz 仅更新现有课程价格与说明

- 管理员“课程平台管理 → 仅更新价格/说明”，独立于导入弹窗；需要 `platform:update`，Benz 原生类型为 `27`。
- 选择已启用接口、远程分类、排除分类与倍率，范围可为全部已关联课程或指定远程商品编号。只读获取上游目录，绝不为未导入商品创建课程。
- 服务端生成五分钟、最多500行的预览，展示本地名称、原价/新价及说明差异。十进制运算，最终四舍五入至两位；负数、溢出、正值不足一分、说明超过500字及重复上游编号均拒绝。
- 用户显式确认后只更新预览中的价格与已提供说明，不重新查询上游，不改名称、分类、排序、上下架、接口或密码规则；缺失说明保留原内容，明确空串可清空。
- 先锁定供应商与批次，再按本地ID锁定全部目标行；价格、说明或绑定被他人修改则整批 STALE，不覆盖、不部分成功。无关的名称/分类/状态修改会保留。
- 同批次并发或重复确认仅应用一次；响应丢失先查询原批次。若查询显示 READY，可重新显式确认**同一批次**，不自动提交或另建批次。APPLIED、STALE、EXPIRED 均不重放。关闭总开关后仍可读取结果。
- 依赖迁移024，默认关闭。该模式只操作本地课程价格，不向供应商写入、不影响原订单金额、用户余额或账本。

## Benz 执行编号查找与恢复

- 真实订单详情提供“恢复执行编号”。本轮新增主动查找入口：一次只读响应最多1000行、最多20个完整匹配候选；不默认选择、不自动分页。超过20个候选或出现畸形/重复编号时整次失败，不截断列表冒充完整结果。身份缺失或不同的记录不列入；成功空结果与查询失败分别展示，均不表示订单不存在。
- 候选仅返回 `orderId/receiptIds/checkedAt/scope`，scope固定为 `CURRENT_RESPONSE`；无原始响应或其他学生资料。查找前后短事务复核权限及订单/商品/配置/别名快照，HTTP在事务外，最终过滤已有绑定和声明；不创建请求、声明或修改订单。并发变化沿用HTTP400及业务码 `-110`；候选与预览共用每操作者5次/分钟，查询/确认共30次/分钟。429提供重试时间，限流故障503且不执行业务。
- 管理员可按原始回执选择候选，也可手填编号。选择清空旧依据及归属确认；继续填写已核实的依据、确认归属，服务端另行只读查单一次；完整身份一致后展示五分钟预览，再单独确认关联。候选不是授权凭证，也不是自动关联或补单。
- 需要有效账号同时具备 `order:update` 和 `api-provider:update`，服务层重查当前数据库权限。`user/pass/kcname/cid` 必须精确匹配，其中 `cid` 为商品绑定；学校/学生课程编号如有返回也不能矛盾。指定编号必须唯一，拒绝首行猜测、重复JSON键、拼接JSON及异常成功码。

### 4.16 精确计价与冻结单价

- 售价与计费因子相乘后完整保留最多八位小数，仅在计算本次扣款或退款总额时四舍五入到分。例如 `0.499999 × 0.11 × 3 = 0.16499967 → 0.16`，不先舍入单次费用再收取0.17元；低于半分的订单不能因此变成收费订单。
- **启用前必须执行迁移029**：两张服务订单/操作表的 `unit_charge` 从 `DECIMAL(16,6)` 扩为 `DECIMAL(18,8)`，十位整数容量不变。只扩精度，不调整历史订单、READY报价、已付/已退金额或商品价格，也不放宽业务金额上限。
- 历史单价 `0.055000` 仍按 `0.05500000` 使用，不能用现售价格反推旧合同。创建、增次及退款都以冻结单价计算；实际回执次数、报价上限和可退净额继续约束退款。分两次各付0.16元后，六次退款最多0.32元，不能因合并舍入退0.33元。
- 报价保存和订单创建均在事务内读回并核对单价。缺失或只完成部分迁移而导致数据库截位时回滚；不扣款、不派发。正确修复结构后，仍有效的原报价可继续确认。结果不确定时保留实际原扣款，不重复发送。
- `QuoteView.unitCharge` 为可空十进制字符串。确认弹窗按服务器快照显示订单计费单价、数量、最终舍入及退款上限说明，不在浏览器算钱；总公里服务保留专用计划摘要。旧响应缺少该字段时不猜测单价。
