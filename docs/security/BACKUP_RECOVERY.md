# 备份与恢复（RPO/RTO）

## 目标
| 项 | 目标 |
|----|------|
| RPO | ≤ 24h（核心资金表建议 ≤ 1h 若开启 binlog 实时备份） |
| RTO | ≤ 4h（同城从库提升） / ≤ 24h（全量备份恢复） |

## 备份对象
1. MySQL：`online_course` 全库 + binlog
2. Redis：AOF/RDB（会话/限流可接受丢失）
3. 配置与密钥：仅密钥管理系统/加密备份介质，不进 Git
4. 对象存储/上传文件（如有）

## 备份策略（建议）
- 每日逻辑备份：`mysqldump --single-transaction --master-data=2`
- 保留 7 日日备 + 4 周周备
- 备份文件加密后异地存放
- 每周自动恢复演练到隔离环境

## 恢复步骤（概要）
1. 冻结写流量 / 维护页
2. 从最近全量备份恢复
3. 按 binlog 追平到故障点前
4. 校验：`sys_user` 余额 vs `account_ledger` 汇总、最近支付订单状态
5. 跑 `PaymentReconcileService.reconcile(昨天)`
6. 恢复只读验证 → 开放写流量
7. 记录事件：时间线、影响面、数据差异、责任人

## 验证清单
- [ ] 管理员可登录（含 MFA）
- [ ] 用户余额与流水一致
- [ ] 支付回调验签成功
- [ ] 外部 API Key 仍可用
- [ ] 安全审计日志可查询
