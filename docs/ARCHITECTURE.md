## 后端分层架构

### 1. Controller层（接口层）
**职责**: 接收HTTP请求，参数校验，调用Service，返回响应

**特点**:
- RESTful API设计
- 统一响应格式
- 自动参数校验（@Valid）
- Swagger文档注解

**示例**:
```java
@RestController
@RequestMapping("/users")
public class UserController {
    @PostMapping
    public Result<Long> createUser(@Valid @RequestBody UserCreateRequest request) {
        // 调用Service处理业务
    }
}
```

### 2. Service层（业务层）
**职责**: 业务逻辑处理，事务管理，调用Mapper

**特点**:
- 接口+实现类设计
- @Transactional事务控制
- 业务规则验证
- 日志记录

**示例**:
```java
@Service
@Transactional
public class UserServiceImpl implements UserService {
    public Long createUser(UserCreateRequest request) {
        // 1. 参数验证
        // 2. 业务逻辑
        // 3. 数据持久化
        // 4. 日志记录
    }
}
```

### 3. Mapper层（数据访问层）
**职责**: 数据库CRUD操作

**特点**:
- 继承MyBatis Plus BaseMapper
- 自动CRUD方法
- 支持自定义SQL
- 分页支持

**示例**:
```java
@Mapper
public interface UserMapper extends BaseMapper<User> {
    // 继承后自动拥有insert、update、delete、select等方法
}
```

### 4. Entity层（实体层）
**职责**: 数据库表映射对象

**特点**:
- @TableName注解映射表名
- @TableField注解映射字段
- Lombok简化代码
- 支持自动填充

### 5. DTO/VO层（数据传输对象）
**职责**: 接口请求响应对象

**特点**:
- DTO: 接收前端请求参数
- VO: 返回给前端的数据
- 参数校验注解
- 隐藏敏感字段

## 前端架构

### 1. 路由层（Router）
**职责**: 页面路由配置，导航守卫

**特点**:
- Vue Router 4
- 懒加载
- 路由守卫（权限检查）
- 动态路由

### 2. 状态管理（Pinia）
**职责**: 全局状态管理

**特点**:
- 用户信息存储
- Token管理
- 登录状态
- 轻量级（相比Vuex）

### 3. API层
**职责**: 封装后端接口调用

**特点**:
- Axios封装
- 统一请求拦截
- 统一响应处理
- 错误处理

### 4. 视图层（Views）
**职责**: 页面组件

**特点**:
- Composition API
- 响应式设计
- Element Plus组件
- 模块化

## 数据流向

### 用户登录流程

```
用户输入账号密码
    ↓
前端验证表单
    ↓
发送POST /auth/login
    ↓
后端Controller接收
    ↓
Service验证用户
    ↓
查询数据库
    ↓
生成JWT Token
    ↓
返回Token给前端
    ↓
前端保存Token
    ↓
自动跳转首页
```

### 创建订单流程

```
用户填写订单信息
    ↓
前端验证表单
    ↓
发送POST /orders（带Token）
    ↓
后端JWT Filter验证Token
    ↓
Controller接收请求
    ↓
Service处理业务逻辑：
  ├─ 查询用户余额
  ├─ 查询课程平台
  ├─ 计算订单金额
  ├─ 检查余额是否充足
  ├─ 检查是否重复下单
  ├─ 创建订单记录
  ├─ 扣除用户余额
  └─ 记录操作日志
    ↓
Mapper执行数据库操作
    ↓
返回订单ID
    ↓
前端显示成功消息
```

## 安全设计

### 1. 认证机制
```
JWT无状态认证
    ├─ Token签名验证
    ├─ Token过期检查
    ├─ 自动刷新Token
    └─ Token黑名单（可选）
```

### 2. 权限控制
```
多级权限
    ├─ 管理员（UID=1）
    ├─ 普通代理
    └─ 数据权限隔离
```

### 3. 数据安全
```
数据保护
    ├─ 密码BCrypt加密
    ├─ SQL注入防护（MyBatis Plus参数化）
    ├─ XSS防护（参数校验）
    └─ CSRF防护（无状态设计）
```

## 数据库设计原则

### 1. 命名规范
- 表名：小写字母+下划线
- 字段名：小写字母+下划线
- 索引名：idx_字段名

### 2. 字段类型
- 主键：BIGINT（支持大数据量）
- 金额：DECIMAL(10,2)（精确存储）
- 时间：DATETIME
- 状态：TINYINT
- 文本：VARCHAR/TEXT

### 3. 索引设计
- 主键索引
- 唯一索引（username, invite_code）
- 普通索引（查询频繁的字段）
- 复合索引（多条件查询）

## 技术选型理由

### 后端：Spring Boot
1. **成熟稳定**: 企业级框架
2. **生态丰富**: 大量第三方库
3. **开发效率**: 自动配置
4. **易于部署**: 内嵌Web容器
5. **社区活跃**: 问题易解决

### 前端：Vue 3
1. **渐进式**: 易于上手
2. **性能优秀**: 虚拟DOM
3. **组件化**: 代码复用
4. **生态丰富**: Element Plus等
5. **响应式**: Composition API

### 数据库：MySQL
1. **成熟稳定**: 广泛使用
2. **性能优秀**: 适合OLTP
3. **社区支持**: 资源丰富
4. **免费开源**: 降低成本

## 符合SOLID原则

### S - 单一职责
每个类只负责一件事：
- Controller只处理HTTP
- Service只处理业务
- Mapper只访问数据

### O - 开闭原则
对扩展开放：
- 接口化设计
- 易于添加新功能

### L - 里氏替换
子类可以替换父类：
- Service接口设计
- 多态应用

### I - 接口隔离
接口职责单一：
- 细粒度接口设计
- 不强迫实现不需要的方法

### D - 依赖倒置
依赖抽象不依赖具体：
- Spring DI/IoC
- 接口注入
