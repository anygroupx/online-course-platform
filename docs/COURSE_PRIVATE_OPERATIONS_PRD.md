# 密价运营中心产品要求

本期目标为可配置、可审计的 A 长期预存、B 限时预存、C 消费续期、D 阶梯成长。阶梯是规则组合维度，不建立新的钱包；H 战略代理复用定制套餐和审核。限量、返利、收费会员仅预留，禁止真实发放或自动扣费。示例金额与档位只用于开发，不是正式售价。

代理流程为发现公开套餐、确认发布版本、申请、预存满足资格、按专户价格成交、查看服务端进度、续期或升级、申请转回剩余余额。管理员需要套餐、代理协议、权益周期、资金退出及运营分析五类页面。所有页面需要明确加载、空数据、失败重试、权限提示、移动端及暗色状态。

管理员按课程商品维护固定价格、门槛、期限、续期/升级及资金政策；发布保存不可变版本。没有核验成本不能发布，低于或等于成本需要独立风险批准。停售阻止新销售，存量约定续期继续按冻结规则。

原协议保存代理与商品唯一关系、全局状态和当前周期；每期独立保存规则、资格来源、时间及成交快照。初次开通和终止后重新签约分开，重新签约复用钱包和历史并增加关系代次。旧协议不得自动改价、补期限、重算本金或猜测历史订单完成时间。

余额不足、暂停或到期不得自动按普通价扣普通余额。若套餐允许普通价选项，必须由代理显式确认、后端重新报价和校验资金来源。购买期结束与原订单观察期分别显示；观察期不延长优惠购买。

到期或未达标后余额保留，代理可申请转回。申请不是已转账，不冻结资金；批准时资金不足保留待处理状态。退款只按原成交金额与原资金来源处理，不根据新价格追收差价。

页面和通知必须从服务端获取权威消费、资格、差额和时间，不使用浏览器订单列表计算资格。不泄露其他代理的密价、余额、内部用户 ID、学生口令或上游凭证。

完成标准覆盖全部服务、页面、通知、旧逻辑、并发、真实 MySQL、必需 GitHub CI、安全扫描、七份文档和可审查提交。当前服务端已接入发布、资金退出、首开/重签、结算、续期、补授及升级；管理员与代理页面、分析和站内通知已接入；旧配置同步、退款复核处理和普通价显式购买已接入；远程 CI 与完整交付审查仍待完成，整体尚未交付或部署。


套餐支持复制为独立草稿、按代理真实费率计算普通参考价和聚合影响范围；旧隐藏编码禁止被现代草稿占用。周期详情提供真正分页的原订单明细、达标差额、待结算单和历史事件。原专户完整流水与转回审核相互连接，分析展示资金对账异常及证据不足。

站内通知轮转当前代次，也提醒保留有限期限的旧协议；不补发虚构的旧激活通知，不猜测旧消费或首次预存。近7/30天激活代理去重，旧配置追加快照不会重复当作新激活。账户切换立即清空私有视图并隔离迟到响应；页面缓存按账户与路由共同识别。
